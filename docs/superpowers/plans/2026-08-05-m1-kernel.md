# M1 Kernel Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved, hand-written Nutanix provider kernel without adding a product Terraform type or a Nutanix SDK.

**Architecture:** `provider` manually composes immutable auth, origin-bound transport, neutral task, and capability values. Namespace adapters alone own operation policies and Nutanix DTO decoding; services receive only their own narrow provider-data ports and cannot execute raw transport operations.

**Tech Stack:** Go 1.26.5, Terraform Plugin Framework 1.19.0, Plugin Protocol 6, Framework Validators 0.19.0, Plugin Log 0.10.0, google/uuid 1.6.0, standard `net/http`, `httptest`, `testing/synctest`, Podman through `./dev`, and Beads 1.1.2.

---

## Execution rules

- Work only in `sprint/m1-kernel` and its dedicated worktree.
- Keep exactly one listed Beads task in progress.
- Start every production behavior with a focused failing test and record the
  expected RED output before implementation.
- Run every Go, Terraform, Task, Beads, Python, generation, and packaging
  command through `./dev`.
- Use the locked Prism v4.3 OpenAPI and error artifact for every operation
  policy and DTO. Never copy implementation code from an SDK.
- After each task, run its focused tests, `./dev task go:test`,
  `./dev task go:test:race`, and `./dev task all`; attach evidence before
  closing its Beads task.
- After every Beads close/start transition, run this exact projection gate
  before committing:

  ```text
  ./dev beads export --output .beads/issues.jsonl
  ./dev task roadmap:generate
  ./dev task tracker:check
  ./dev task roadmap:check
  ./dev task docs:check
  ```

- Commit only the reviewed task scope with a `Refs: ntnx-m1.N` trailer.

## Completion boundary

M1 is complete only when all nine tasks are closed with evidence, the approved
provider contract matches generated documentation, the full local and exact-SHA
CI gates pass, and no product Terraform type or live mutation has entered the
branch. Partial kernel packages, subset tests, an unavailable live target, or a
plan without implementation remain `IN_PROGRESS`.
